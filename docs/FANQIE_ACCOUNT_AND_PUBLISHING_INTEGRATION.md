# 番茄账号管理与自动发布集成边界

## 来源与取舍

本次仅审计 `WTW-NiuBi/tomato-novel-mcp-tool` 的账号会话与章节发布思路，审计基线为提交：

`ad24934df55d45e166e9423d0f4a78461a19c83d`

没有复制该项目源码。仓库根目录没有可核验的 `LICENSE` 文件，且实际实现包含自动填写账号密码、将 Cookie 明文保存到 JSON、旧页面选择器以及与账号无关的 AI 生成、原创检测、数据分析和任务调度依赖。这些内容全部不进入 Tomota。

## 已集成能力

- 多账号本机显示名称、切换、独立浏览器资料目录、会话关闭和本地归档。
- 登录状态检查、会话复用和失效后重新打开可见浏览器。
- 不读取、不导出 Cookie、Token、密码、验证码或二维码内容。
- 账号归档只隐藏 Tomota 入口，不删除浏览器资料目录，不改动番茄云端账号或作品。
- 发布批次绑定账号和番茄平台作品 ID，禁止仅凭书名猜测目标作品。
- 只允许通过 Tomota 严格质量闸门的章节进入发布批次。
- 支持立即提交审核或由番茄平台执行定时发布。
- 写入前校验正文哈希、账号、作品 ID、重复章节和即时确认；结果不确定时停止并要求重新同步。

## 明确未集成

- 外部项目的账号密码自动登录和 Cookie JSON 文件。
- 外部项目的 OpenAI、Anthropic、Redis、TypeORM、node-cron、原创检测、内容生成、数据分析和所谓风控规避能力。
- 自动处理验证码、实名、人脸、合同、收益、银行卡、税务或安全设置。
- 删除作品、删除已发布章节、撤回公开内容或在结果不确定时自动重试。

## 发布确认模型

一次自动发布仍需要三层即时确认：

1. `PUBLISH <batch-id>`：确认准确批次。
2. `WRITE <batch-id>`：确认这一次浏览器实际写入。
3. `SUBMIT <batch-id>:<chapter>:<hash12>`：确认每章及其当前正文哈希。

确认后，Tomota 可以自动填写章节、设置平台排期并逐章提交；排期后的实际公开由番茄平台执行。页面结构变化、登录失效、网络中断或官方结果不明确时，任务立即停止，不盲目续传。
