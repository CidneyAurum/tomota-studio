# 作者补充规则

这份文件是作者对 `webnovel-writing` 的明确补充要求。它不替代原有模块，只在正文生成、对白修复、去 AI 味和完稿审查时叠加执行。

## 一、人物声音

1. 人物性格不同，必须体现在说话方式和语气上。动笔前先确定人物的身份、年龄、教养、关系位置、当前目的和受压方式。
2. 主要人物至少保留一项可辨识的语言习惯：句子长短、称呼、口头习惯、回避方式、是否爱反问、是否把话说满等。
3. 不允许所有角色都使用完整、礼貌、解释充分的长句；但也不能为了去 AI 味而把每一句都切成短问短答。
4. 对白必须改变关系、暴露信息、形成施压或推动决定；低价值对白应改成动作、环境或叙述。

## 二、日常说话与对话密度

1. 日常说话要有省略、停顿、接不上话、改口、回避、答非所问和口头习惯，不要像会议纪要、心理分析报告或任务说明书。
2. 连续问答超过两三轮时，检查是否有信息可以交给动作、物件或现场变化；对白密度必须服从场景承载力。
3. 高压对白可以短，但不能让人物连续机械地一问一答。保留真正改变局面的刀口，其余删掉或合并。
4. 人物不能把自己不知道的背景替作者讲出来；设定优先通过误解、试探、具体档案和行动暴露。

## 三、伏笔与读者可理解性

1. 正常伏笔可以隐藏原因、身份和最终真相，但必须让读者知道具体对象、事件或异常是什么。
2. 不得用未定义名词、悬空指代、混用文书名称或无依据的玄虚比喻制造神秘感。
3. 首次出现的文件、印记、规则、组织、称谓和特殊动作，必须在同一场景给出最小必要定义。
4. 写完后检查：读者是否能回答“谁在做什么、手里拿的是什么、这句话指向什么”；如果不能，先补清楚，再保留谜底。
5. “读者暂时不知道真相”是伏笔；“读者不知道作者在说什么”是表达缺陷，必须修复。

## 四、完稿自检

- 把每个主要角色的台词单独摘出来，换成另一个角色后是否仍然成立？如果成立，补身份差。
- 每一段对白是否至少完成信息、关系、压力或行动中的一项？否则删减。
- 名词是否前后一致，例如记录簿、处刑名册、原判、葬钟印不能无说明地互换。
- 章末保留核心悬念，但不留下无指代、无对象、无动作逻辑的句子。
